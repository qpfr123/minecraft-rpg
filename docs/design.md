# 마인크래프트 RPG 설계안 — 초기 구현 계획

기준: 2026-09-24 원본 명세 `message.txt`와 검토 결과, 같은 날 14:52 선택. 2026-09-23 설계안에 기록된 **이전 결정**(전투 중 직업 전환, 전 포인트 수동 배분과 단일 스탯 50% 상한, 정신 추가, 효율=작업 속도, 방어막 상한, 시전 중 교체 제한)을 이어받았다. 이번에 **시험 계수를 초기 구현 계수로**, **Paper 1.21.11 / Java 21 / Gradle Kotlin DSL / SQLite 조합을 구현 기반으로** 채택했다. 아래 수치는 첫 구현 기준이며 플레이 테스트로 조정할 수 있다.

## 확정된 핵심 규칙

- **직업 태그는 전투 중 직업을 교체하며 싸우는 방식**이다. 여러 직업을 해금할 수 있지만, 전투 효과와 스킬은 그 순간 활성화된 직업 하나를 기준으로 계산한다. 메인/서브 동시 조합은 이번 범위에서 제외한다.
- **2차 스탯은 최초 10점과 레벨업당 3점을 전부 수동 배분**한다. 한 스탯의 영구 투자량은 전체 지급 포인트의 50%를 초과할 수 없다. 직업 가중 자동 배분은 사용하지 않는다.
- **정신은 7번째 2차 스탯**, 생활 기술의 **효율은 작업 속도**, 방어막 총량 상한은 **최대 HP의 50%**로 확정한다.
- 직업 태그의 추가 슬롯·교체 비용은 진입장벽을 만들지 않는다. 최초 설계는 **교체 재화 비용 0, 추가 슬롯 구매 없음**으로 제안한다. 남용 방지는 비용이 아닌 전투 중 교체 쿨타임으로 해결한다.
- 50% 상한은 한 스탯 몰빵을 막지만, 두 스탯 조합의 우세까지 막지는 못한다. 아래 점당 기여 계산과 직업별 플레이 테스트를 함께 통과시켜야 한다.

수동 배분이어도 특정 직업에 맞춘 투자 편향은 남는다. 전투 중 자유로운 교체가 핵심이므로 직업 보너스는 영구 투자로 적립하지 않고 **활성 직업에 따라 동적으로 계산**한다. 그래도 전환 후 빌드가 약해지는 문제가 크면 직업별 프리셋이나 제한적 재분배를 별도 검토한다.

## 원문 명세 정리와 정정

1. `HP 증가`의 설명은 데미지 증가가 아니라 **최대 HP를 해당 비율만큼 증가**로 정정한다. 현재 HP와 최대 HP를 별도 저장한다.
2. `ATK`는 소수 연산이 필요한 **0 이상의 double**로 통일한다. 화면 표시는 반올림해도 내부 계산값은 유지한다.
3. 방어막은 HP 재생으로 회복되지 않는다. **방어막 부여 스킬 또는 소모 아이템**만 방어막을 더하며 총량은 최대 HP의 **50%**가 상한이다. 부여량은 콘텐츠별 데이터로 정의한다.
4. MP 성장 링크가 없으므로 이전 결정대로 2차 스탯 **정신**을 7번째로 추가한다. `명중`은 명중·회피 규칙이 없으므로 **집중**으로 개명한다. 명중·회피 자체는 MVP에 넣지 않는다. 정신·집중에는 채택한 초기 구현 계수를 적용한다.
5. 아이템 증폭은 **아이템 종류/드롭 테이블 항목별로, 드롭된 전체 수량에 한 번만 판정**한다. 성공하면 동일 수량을 한 번 더 지급한다(2개 → 4개). 아래 확률식의 `p`는 드롭 보너스 반영 후 실제 1차 드롭 확률로 제안한다.

## 설계 원칙

- 1차 스탯은 원천값만이 아니라 장비·버프·2차 스탯을 계산한 **행동 시점의 최종 상태값**이다. 기록값(현재 HP/MP/방어막)과 계산값(최대 HP/ATK 등)을 분리한다.
- 2차 스탯은 전부 수동 배분하고 50% 투자 상한을 적용한다. 상한과 배분 방식은 서로 다른 규칙이다.
- 직업 데이터는 단일 enum이 아니라 해금·스킬·동적 보너스를 가진 정의로 둔다. 플레이어는 전투 중 활성 직업을 교체할 수 있다.
- 생활 기술은 전투 수치 전체를 공유하지 않는다. 원문에서 이미 연결된 1차 보너스와 소수의 2차 교차 효과만 쓴다.
- 다른 플레이어의 **표시 숨김**과 몬스터의 **독립 인스턴스**는 다른 문제다. 초기 버전에서 완전한 1:1 월드 격리를 약속하지 않는다.

## 구현 전제와 피해 경계

- **채택한 구현 기반:** Paper **1.21.11**, Java **21**, Java 소스와 Gradle Kotlin DSL, SQLite. Folia는 이번 MVP 대상에서 제외한다. Folia의 엔티티 스케줄러는 엔티티가 속한 지역 스레드에 작업을 보내는 API이지 플레이어별 독립 월드를 만들지 않는다. 서버 버전은 구현 착수 시 지원 빌드에 고정한다.
- **HP 권한:** RPG의 현재/최대 HP(기본 100)를 서버의 권위 상태로 저장한다. 바닐라 체력은 HUD·사망 연동용으로 표시한다. 현재 RPG HP가 양수라면 표시 체력을 `max(0.5, 20×현재RpgHP/최대RpgHP)`로 유지하고, 0일 때만 바닐라 체력을 0으로 만들어 사망 처리한다. 표시용 반올림이 살아 있는 플레이어를 죽이지 않도록 한다. 방어막과 MP도 별도 상태이며 바닐라 흡수 하트는 쓰지 않는다. 바닐라 포만감·물약·비콘 등의 자동 체력 회복은 RPG HP와 표시 HP를 어긋나게 하므로 RPG 플레이어의 `EntityRegainHealthEvent`를 취소하고 허용한 회복만 `HealService`로 처리한다. 사망 연동에는 재진입 표식을 둔다.
- **피해 진입점:** `EntityDamageEvent`는 바닐라 공격·낙하·화재 등의 **Paper 이벤트 경계**로 쓴다. RPG 스킬처럼 플러그인이 직접 만든 피해는 `DamagePipeline.apply(DamageRequest)`로 들어간다. 이벤트 어댑터는 이미 취소된 이벤트를 무시하고 해당 이벤트를 취소한 뒤 같은 파이프라인을 호출한다. 모든 RPG HP 변경은 이 파이프라인과 명시적 회복 API를 통해서만 일어난다. `EntityDamageEvent` 하나가 모든 플러그인 피해를 자동 포착한다는 전제는 두지 않는다.
- **바닐라/장비 규칙:** 기본 근접·투사체 공격은 바닐라 피해를 취소하고 RPG 기본 스킬 피해로 변환한다. 바닐라 갑옷·Protection·Sharpness 등의 바닐라 피해 수식은 사용하지 않는다. 허용 장비의 능력치를 RPG 장비 데이터로 변환해 `StatCalculator`에서 단 한 번 적용한다. 다른 플러그인이 이벤트를 후순위에서 바꾸는 경우 호환성이 깨질 수 있으므로 MVP는 단독 전투 플러그인 구성을 전제로 통합 테스트한다.
- **피해 종류:** RPG 직접 공격/투사체는 `ATK→증가→치명→DEF→방어막→HP→흡수`를 따른다. 낙하·화재·용암·질식·익사·독/위더 등 환경 피해는 바닐라 이벤트의 **원피해량**을 RPG 단위로 `원피해/20×대상 최대HP` 변환해 HP에 직접 적용하며, DEF·방어막·흡수는 적용하지 않는 시험 규칙이다. 최대 HP 100에서는 이전 `×5`와 같고, 성장 후에도 환경 위험의 비율이 유지된다. 폭발은 발생 주체가 몬스터라면 RPG 공격으로, 월드 환경이면 환경 피해로 분류한다. 공허/관리자 처치는 즉사하며 방어막을 우회한다. 환경 피해의 상태이상·내성 예외는 콘텐츠 데이터에 명시한다.
- **RPG 몹 HP:** `MobStatProfile`이 몹 종류별 최대 HP·ATK·DEF·상태 저항·전리품 테이블을 정의하고, 엔티티 PDC의 프로필 ID로 연결한다. `MobHealthState`가 현재 HP·소유자/파티·처치 처리 여부를 관리한다. 태그된 몹에 대한 기본/스킬/환경 피해도 `DamagePipeline`이 한 번만 처리한다. HP 0에서 킬 소유권과 보상 원장 기록을 확정한 뒤 바닐라 엔티티 사망으로 연결하고, 청크 언로드/로드 시 남은 HP를 PDC에 저장·복원한다. 태그가 없는 바닐라 몹은 이 파이프라인의 대상이 아니다.
- **저장:** SQLite를 단일 서버의 초기 권위 저장소로 선택한다. `PlayerProfileRepository`가 프로필/포인트/쿨타임/생활 EXP를 트랜잭션과 버전 번호로 저장하고, 보상 원장은 이벤트 ID의 유니크 제약으로 **논리적 보상 생성**의 중복을 막는다. 실제 아이템 인벤토리 지급은 DB 트랜잭션과 원자적으로 묶을 수 없으므로 보상함/수령 상태를 별도로 설계하고, 충돌 시 수령 내역을 복구·대조한다. Paper 메인 스레드에서는 읽기·쓰기 I/O를 기다리지 않고 전용 DB 실행기에 위임한다. 로그인 시 로드가 끝나기 전 조작을 잠그고, 종료 시 대기 중인 쓰기를 플러시한다. PDC는 아이템·RPG 몹의 **종류/소유 ID 표식**에만 사용하며 플레이어 성장 데이터의 원본으로 삼지 않는다. 다중 서버가 필요해지면 DB 선택을 재검토한다.

이 경계에서 기본 스킬, RPG 스킬, 낙하/환경, 방어막, 치명타, 타 플러그인 취소 이벤트, 사망/재접속을 각각 재현한다. 피해 이벤트의 `getDamage()`와 `getFinalDamage()`를 섞어 바닐라 갑옷과 RPG DEF를 이중 적용하지 않는다. `getFinalDamage()`는 바닐라 감소 후 값이므로 이 설계의 원피해 기준이 아니다.

## 플레이어 데이터 모델

| 묶음 | 영속 데이터 | 파생/일시 데이터 |
| --- | --- | --- |
| 식별·성장 | UUID, 레벨, 현재 EXP, 누적 획득 포인트 | 다음 레벨 필요 EXP |
| 스탯 | 2차 스탯별 수동 투자량, 미사용 포인트, 규칙 버전 | 장비·버프·활성 직업 보너스 포함 1차 최종값 |
| 자원 | 현재 HP, MP, 방어막 | 최대 HP/MP, 초당 회복량 |
| 직업 | 해금 직업 태그, 현재 활성 직업, 마지막 교체 시각 | 현재 사용 가능한 스킬, 직업별 동적 보너스 |
| 생활 | 벌목·채집·채광별 레벨/EXP | 효율·드롭·증폭·EXP 보너스 |
| 협동 | 파티 ID 또는 없음 | 가시성·인스턴스 소유자/공유자 |

스탯은 기본값·장비/버프의 고정값을 먼저 합산하고, 2차 스탯·직업의 비율 보너스를 적용한 뒤 상·하한을 적용한다. 활성 직업 보너스는 영구 투자량에 합치지 않는다. 퍼센트는 저장 시 `0.10 = 10%` 형태로 통일한다. 현재 자원은 직업 교체 등으로 최종 최대치가 바뀌면 새 최대치를 넘지 않게 자르고, 교체만으로 HP/MP를 무료 회복하지 않는다. 사망·접속 종료·직업 교체·파티 변경 시 파생값과 가시성 캐시를 다시 계산한다. 경제 보상은 이벤트 ID로 원장에 한 번만 생성하고 실제 아이템 수령은 별도 상태로 관리한다.

## 1차 스탯 레지스트리

표의 `int+`는 0 이상의 정수, `double+`는 0 이상의 유한 소수다. `cap`은 최종값의 경계다. 원문에서 상한이 `int`로만 표현된 값은 임의의 고정 상한을 만들지 않는다.

| 스탯 | 타입 / 범위 | 초기값 | 계산·적용 규칙 |
| --- | --- | --- | --- |
| 현재 HP / 최대 HP | int+ / int≥1 | 100 / 100 | 초기 구현식: 최대 HP = `floor((100 + 장비HP) × (1+0.006×건강+HP증가))`; 현재 HP 0이면 사망 |
| 방어막 | int, 0~`floor(최대HP×0.5)` | 0 | 피해에 먼저 소모; 스킬/아이템으로만 회복, 총량 상한은 최대 HP 50% |
| 현재 MP / 최대 MP | int+ / int≥1 | 100 / 100 | 초기 구현식: 최대 MP = `floor((100 + 장비MP) × (1+0.006×정신))`; 스킬 비용 차감 |
| HP Regen / MP Regen | double+ | 각 4 | 초기 구현식: 각각 `4 + 장비·버프 + 0.1×건강/정신`; 전투 중 20%, 비전투 중 100% 적용, 소수 누적 후 정수 회복 |
| ATK | double+ | 10 | 초기 구현식: `(10 + 장비·버프 고정 ATK) × (1+0.006×근력/마력)`; 물리·마법 공통 공격력 |
| DEF | 비율 0~0.50 | 0 | 원문식: `clamp(장비·버프 + 0.002×저항)`; RPG 전투 피해 감소율 |
| 상태이상 저항 | 비율 0~0.70 | 0 | `clamp(장비·버프 + 0.002×저항)`; 디버프 지속시간에 `(1-저항)` 적용 |
| 크리티컬 확률 | 비율 0~1 | 0.10 | 초기 구현식: `clamp(0.10 + 장비·버프 + 0.006×집중)` |
| 크리티컬 데미지 | 비율 0~4 | 0.50 | 초기 구현식: `clamp(0.50 + 장비·버프 + 0.01×집중)`; 치명타 배율은 `1+이 값` |
| 공격 속도 | 비율 0~3 | 1.00 | 초기 구현식: `clamp(1 + 장비·버프 + 0.006×민첩)`; 기본 스킬 간격 = `기본 간격 / max(공격속도, 0.01)` |
| 스킬 쿨타임 감소 | 초 0~10 | 0 | 기본 스킬 외 `max(min(원래 쿨타임, 5초), 원래 쿨타임 - 감소초)`; 원래 쿨타임 3초라면 늘어나지 않음 |
| 흡수 | 비율 0~0.20 | 0 | 실제 HP 피해량 × 흡수율만큼 회복(방어막 피해·초과 피해 제외) |
| HP 증가 | 비율 0 이상 | 0 | 최대 HP에 적용; 밸런스 상한은 추후 확정 |
| 데미지 증가 | 비율 0 이상 | 0 | `기본 스킬 계수 × ATK × (1+데미지 증가)`에 적용 |
| 효율 | 비율 0~3 | 1.00 | 확정 의미는 작업 속도; 제안 공식 `작업 시간 = 기본 작업 시간 / max(효율, 0.01)`; 수량 증가는 별도 |
| 아이템 드롭율 보너스 | 비율 0~2 | 0 | 항목별 `p = min(1, 기본 드롭 확률 × (1+보너스))` |
| 아이템 증폭 | 비율 0~0.50 | 0 | 1차 드롭 성공 시 해당 항목 수량에 한 번 `p × 증폭` 확률로 추가 지급 |
| 경험치 획득 보너스 | 비율 0~5 | 0 | 전투·생활 각각 `floor(기본 EXP × (1+보너스))` |
| LV / EXP | int≥1 / int+ | 1 / 0 | EXP가 다음 레벨 필요량에 도달하면 차감·레벨업 반복; 필요량 곡선은 별도 밸런싱 |

RPG 전투 피해 순서: `ATK×스킬계수 → 데미지 증가 → 크리티컬 → DEF → 방어막 → HP → 흡수`. 상태이상 저항은 면역 확률이 아니라 **지속시간 감소**다. 이동속도는 원문 1차 목록에서 빠져 있으므로 별도 파생 속성으로 두고 `기본 이동속도 × (1+0.004×민첩+기타 보너스)`를 제안한다. 치명타·방어막·피해의 중간 계산은 소수로 유지하고 HP를 실제 차감할 때만 소수 잔여를 누적해 정수화한다. PvP는 MVP에서 비활성화한다.

## 2차 스탯과 포인트 배분

| 스탯 | 점당 효과 | 생활 기술 교차 효과 |
| --- | --- | --- |
| 근력(마력) | 초기 구현값: 장비 포함 고정 ATK에 +0.6%/점 | 없음; 마법 태그에서는 표시명만 마력, 투자량은 같은 공격력 축 |
| 민첩 | 초기 구현값: 이동속도 +0.4%p, 공격속도 +0.6%p/점 | 초기 구현값: 효율 +0.2%p/점, 생활 기술에만 적용 |
| 저항 | **원문 유지:** DEF +0.2%p, 상태이상 저항 +0.2%p/점 | 없음; 방어 특화 직업의 방어막·상태이상 대응 스킬과 별도 시너지 검증 |
| 건강 | 초기 구현값: 최대 HP +0.6%, 기본 HP Regen +0.1/점 | 없음 |
| 집중(구 명중) | 초기 구현값: 크리티컬 확률 +0.6%p, 크리티컬 데미지 +1.0%p/점 | 없음 |
| 행운 | 아이템 드롭율 보너스 +0.4%p | 원문 효과 그대로 생활 드롭에도 적용; **증폭 추가 연동은 보류**해 중첩 경제 효과를 피함 |
| 정신(7번째 확정) | 초기 구현값: 최대 MP +0.6%, 기본 MP Regen +0.1/점 | 없음 |

- **확정 배분:** 최초 10점과 레벨업당 3점을 전부 플레이어가 직접 배분한다. 직업 교체는 투자량을 변경하지 않는다.
- **확정 상한:** 한 스탯의 누적 영구 투자량은 전체 지급 포인트의 50%를 초과할 수 없다. 이는 소프트캡이 아닌 투자 상한이다. 배분 UI는 상한에 도달한 스탯을 비활성화하며, 초기 10포인트에도 적용한다.
- 미사용 포인트는 보관할 수 있지만 상한 계산의 분모는 **지급한 총 포인트**로 고정한다. 서버는 배분 요청을 원자적으로 검증·기록해 상한 우회와 중복 투자를 막는다.
- 50% 상한은 단일 축 독점을 막지만, 특정 2스탯 조합이 지배적일 가능성까지 제거하지는 못한다. 레벨 1·10·30·60 시뮬레이션으로 빌드 다양성을 검증한다.

### 밸런스 진단과 채택한 초기 계수

원문 계수에서는 장비와 버프가 없는 레벨 1의 첫 근력 1점이 ATK를 10% 올리지만, 민첩의 첫 1점은 기본 공격 DPS를 약 0.4%, 명중의 첫 1점은 기대 치명타 DPS를 약 0.14% 올린다. 건강 10점이면 HP 160에 HP Regen 14/초가 되어 비전투·전투 구분 없이 약 8.75%/초를 회복한다. 단일 투자 50% 제한만으로는 `근력+건강` 쏠림을 막기 어렵다는 점은 검토에서 확인했다.

채택한 초기안은 검토에서 나온 (a) 방향을 택하되 **근력만 %로 바꾸는 것으로 끝내지 않는다**. 장비가 고정 ATK/HP/MP의 성장분을 담당하고, 전투 2차 스탯은 위 표의 상대 효과로 바꿔 비교한다. **저항의 DEF 계수는 의도한 낮은 방어력에 맞춰 원문 0.2%p/점으로 유지**한다. 저항은 상태이상 지속시간 감소와 방어 특화 직업 스킬의 방어막·상태이상 대응으로 가치를 보전한다. 예를 들어 해당 직업의 방어막 부여량에만 `1+0.005×저항` 배율을 주되 최대 HP 50% 상한은 유지하는 안을 추후 시뮬레이션한다. 이 직업별 시너지는 별도 밸런스 가정이다. 원문 계수는 비교 자료로 보존한다. `행운`은 DPS가 아니라 시간당 재료 획득량, `정신`은 MP가 병목인 스킬 순환에서 비교한다.

아래 표는 **다른 투자·장비·버프 없음**, 기본 치확 10%·치명 피해 +50%, 기본 공격의 쿨타임만 공속 영향을 받음, DEF 이외 피해 감소 없음으로 계산했다. 각 행은 해당 레벨에 지급된 포인트의 50% 상한보다 **한 점 적게** 해당 스탯에 투자한 상태에서 다음 1점을 투자할 때의 상대 변화다. DPS는 지속 기본 공격의 기대값, EHP는 일정한 RPG 전투 피해를 버티는 양이며 리젠·상태이상·이동 효과는 별도다. 장비 수치를 포함해도 채택한 초기안의 상대 기여는 이 조건에서 같다.

| 레벨 | 총 지급/단일 상한 | 비교 시작점 | 근력 DPS | 민첩 DPS | 집중 DPS | 건강 EHP | 저항 EHP | 값 상한에 닿는 레벨(이론상) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 10 / 5 | 4점 | +0.586% | +0.586% | +0.426% | +0.586% | +0.202% | 아래 참조 |
| 10 | 37 / 18 | 17점 | +0.544% | +0.544% | +0.537% | +0.544% | +0.207% | 아래 참조 |
| 30 | 97 / 48 | 47점 | +0.468% | +0.468% | +0.708% | +0.468% | +0.221% | 아래 참조 |
| **가정 최대 60** | 187 / 93 | 92점 | +0.387% | +0.387% | +0.784% | +0.387% | +0.246% | 치확 98 / DEF 165 / 공속 221 / 치피·상태저항 231 |

계산식: `기대 DPS ∝ ATK × 공격속도 × (1+치확×치명피해증가)`, `EHP ∝ 최대HP/(1-DEF)`이다. **최대 레벨 60은 설계 계산용 가정**이고 아직 확정하지 않았다. 마지막 열은 50% 투자 제한 아래 그 능력치에만 가능한 만큼 투자하고 장비·버프가 없을 때의 최초 도달 레벨이다. 현재 가정 최대 레벨에서는 이 값 상한에 닿지 않는다. 근력·건강에는 정한 값 상한이 없고, MP·HP 재생에는 이 표의 값 상한을 적용하지 않는다. 실제 스킬 DPS는 공속이 기본 스킬에만 적용되므로 민첩의 기여가 이 표보다 작을 수 있다. **집중은 치확×치피의 곱으로 점당 효율이 레벨 60에서 더 커져** 한계 효율이 근력보다 높다. 이를 확정 밸런스로 취급하지 않고 레벨 1·10·30·60의 기본 스킬 위주·스킬 위주·치명 위주·방어 위주 직업/장비별 처치 시간, 받는 피해, MP 고갈, 전리품/시간을 비교한다. 한 조합이 모든 시나리오에서 우세하면 치명 계수와 직업 스킬 계수를 조정한다.

HP/MP 재생은 기본 수치 4/초를 비전투 회복속도로 유지하고, 전투 중에는 채택한 초기 비율 20%만 적용한다. 적대 행동을 하거나 받으면 전투 상태가 되고, 마지막 적대 행동 5초 후 비전투로 돌아가는 시간은 조정 가능한 가정이다. 건강/정신 10점일 때 최대 HP/MP 106, 기본 재생 5/초, 전투 재생 1/초다. 작은 틱마다 소수 잔여를 누적한다. MP 부족 때문에 특정 직업이 멈춘다면 MP 비용·전투 재생률을 함께 조정한다.

## 직업 태그 시스템

`JobTag` 정의에는 ID, 해금 조건, 스킬 ID 목록, 스킬 계열(물리/마법), 동적 직업 보너스, 교체 가능 조건을 둔다. 플레이어는 여러 직업을 해금하되 **한 순간에는 직업 하나만 활성화**하고, 전투 중 해금된 직업으로 전환할 수 있다. 직업 교체는 이미 배분한 2차 스탯을 바꾸거나 영구 포인트를 지급하지 않는다. 전환 시 사용 스킬과 직업 보너스를 재계산한다.

스킬은 활성 직업에서 해금한 목록만 사용한다. **시전 중에는 직업을 교체할 수 없다.** 성공적인 교체 직후부터 모든 직업에 공통으로 적용되는 교체 쿨타임을 둔다. 초기 제안은 **10초**이며 플레이 테스트로 조정한다. 재화 소모는 0으로 시작한다. 직업을 바꿔도 기존 스킬의 남은 쿨타임과 진행 중 효과·만료 시각은 초기화되지 않으며, 스킬 ID와 효과 인스턴스 기준으로 캐릭터에 저장한다. 접속 종료·재접속이나 재교체로도 이를 초기화하지 않는다. 진행 중 효과의 소유/중첩 규칙은 전투 프로토타입에서 정한다. 스킬 개수·계수·직업 해금 레벨도 그때 수치화한다. 물리/마법 계열 모두 같은 ATK를 사용하며 `근력↔마력` 표시명은 현재 활성 직업을 따른다.

방어막 부여량의 **초기 제안**은 일반 방어 스킬 `최대 HP의 15%`, 방어 특화 스킬 `30%`, 소모 아이템 `10%`다. 각 부여 결과는 `min(현재 방어막 + 부여량, floor(최대 HP×0.5))`로 자른다. 스킬별 쿨타임과 아이템 사용 제한을 함께 설계하고, 보스전에서 과도한 방어막 유지가 가능한지 확인한 뒤 부여량을 조정한다.

## 생활 기술 연결

| --- | --- | --- | --- | --- | --- |
| 벌목 | 작업 시간 | 목재 드롭 판정 | 성공 수량 복제 | 벌목 EXP | 민첩→효율, 행운→드롭 |
| 채집 | 작업 시간 | 농작물/채집물 드롭 판정 | 성공 수량 복제 | 채집 EXP | 민첩→효율, 행운→드롭 |
| 채광 | 작업 시간 | 광물 드롭 판정 | 성공 수량 복제 | 채광 EXP | 민첩→효율, 행운→드롭 |
| 몬스터 처치 | 미적용 | 전리품 드롭 판정 | 성공 수량 복제 | 전투 EXP | 행운→드롭 |

생활 행동은 플레이어·자원 노드·작업 시작 시각으로 식별하고, 완료 시 **서버에서 한 번만** 보상을 확정한다. 파티 공유/개인 보상 규칙은 후속 결정이다. `효율`을 수량이 아닌 작업 시간에 연결한 것은 드롭/증폭과 역할이 겹치지 않게 하기 위한 제안이다. 일반 블록 파괴 속도는 서버 타이머만 줄이지 않고 목표 Paper 버전의 `block_break_speed`(필요시 `mining_efficiency`) 속성으로 클라이언트 진행 표시와 맞춘다. 농작물처럼 즉시 파괴되는 작업은 별도 상호작용 UI/타이머가 필요하며 동일 공식의 체감이 보장되지 않는다.

| 2. 공용 필드 | `per-player-mob-spawns`를 부하 측정 후 적용; 소유한 몹의 전리품은 플레이어/파티별 보상 장부, 몹의 첫 타격자/파티 소유권을 제한 시간 부여 | 소유한 몹의 보상이 타인의 습득으로 사라지지 않음 | **필드 몹·블록·AI는 공유**. 첫 타격 독점·가로채기·소유 만료와 파티 전환을 검증 |
| 3. 솔로/파티 던전 | 진입 단위로 템플릿 월드를 복제해 참가자만 입장; 던전 몹·노드·드롭은 월드 안에서만 생성 | 던전 안의 엔티티·블록·AI·전리품을 실제로 분리 | 월드 생성/언로드 비용·남은 엔티티·재접속·파티 해산/합류를 검증. 동시 던전 수 상한과 유휴 인스턴스 정리 필요 |

`hidePlayer`/`showPlayer`와 `hideEntity`/`showEntity`는 **시각적 가시성** API이고, `per-player-mob-spawns`는 몹 수 제한의 계산 방식이다. 이들만으로 각 플레이어에게 독립적인 엔티티 시뮬레이션이 생기지는 않는다. 따라서 공용 필드에서 완전한 1:1 상호작용을 약속하지 않고, 해당 보장은 던전 인스턴스에 한정한다. 던전 템플릿은 실행 중 월드 폴더를 복사하지 않고 정지된 원본에서 준비한다. 월드 생성·언로드는 Paper가 허용하는 메인 스레드 안전 시점에 수행하고, 미리 준비한 소수 인스턴스 풀·동시 수 제한·종료 후 정리를 둔다. 던전에서 나가거나 접속이 끊겨도 소유권과 복귀/폐기 정책을 기록한다.

공용 필드 RPG 몹에 `hideEntity`를 적용하는 대안은 MVP에서 제외한다. 이 방식으로 진짜 분리를 구현하려면 `EntityTargetEvent`, 공격·피해, 충돌, 소리·파티클, 투사체, 보상, 파티 변경을 각각 통제해야 한다. 패킷 기반 가짜 엔티티도 자체 AI·판정 엔진이 필요하므로 MVP 범위에서 제외한다.

**블록은 공유 월드 상태**다. 한 사람이 광석·나무를 캐면 다른 사람에게도 사라진다. 플레이어별 자원 노드는 별도 월드/재생성 또는 `sendBlockChange`를 활용한 가짜 블록 표시를 검토할 수 있다. 단, 가짜 블록은 화면만 바꾸므로 파괴 판정·충돌·보상은 서버 노드 장부와 이벤트 검증으로 따로 구현해야 한다. 숨겨진 플레이어의 채팅·커맨드·충돌·PvP 노출도 각각 정책이 필요하다.
