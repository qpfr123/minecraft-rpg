# 수직 슬라이스 1 — 범위와 통과 조건

기준: 2026-10-03 범위 검토와 같은 날 결정.
설계 원본: [design.md](design.md)

## 결정 사항 (2026-10-03)

- 테스트 서버는 로컬 PC(WSL)에서 실행한다: `scripts/run-server.sh`
- 저장소는 GitHub 원격 저장소로 관리한다.
- **직업은 아이디어만 정리하고 구현하지 않는다**: [job-ideas.md](job-ideas.md)

## 범위

| 포함 | 내용 |
| --- | --- |
| 성장 | 레벨 1~10, 2차 스탯 7종 수동 배분, 단일 스탯 50% 상한 |
| 전투 | `DamagePipeline`, RPG HP와 표시 체력 연동, 방어막, 치명타, 전투/비전투 재생, 환경 피해 변환, 직업 없는 공통 기본 공격 |
| 몹 | 일반 몹 2종, 공용 필드 보스 1개 |
| 장비 | 고정 옵션 장비 3~4개, 몹·보스 드롭으로 획득 |
| 보상 | 보상 원장(이벤트 ID 유니크), 보상함, 지급 중 종료 복구 |
| 소유권 | 공용 보스·몹의 피해 기여 기록, 보상 수령자 결정, 수령자별 중복 방지(`이벤트 ID + 수령자` 유니크) |
| 운영 | SQLite 백업·복원 스크립트, 관리자 조회(프로필, 보상 원장) |

이번 슬라이스에서 제외하는 것: 직업과 직업 교체(결정 사항), 화폐·상점, 거래·강화·경매장, 생활 기술, 던전 인스턴스, 플레이어 숨김, 무중단 리로드, 리소스팩.

## 구현 상태 (2026-10-03)

- 순수 로직 단위·통합 테스트 38개: `./gradlew test`
- 실제 서버 E2E 42개 항목: `EULA_ACCEPTED=true scripts/e2e.sh`. 오프라인 모드 테스트 서버(`run-e2e/`, 127.0.0.1:25599)에 mineflayer 봇 2개를 붙여 아래 통과 조건 2~7을 재현한다.
- 명령어: `/rpg stats`, `/rpg alloc <스탯> <양>`, `/rpg claim`과 관리자용 `/rpgadmin profile|ledger|spawn|backup|level|givegear|crashtest`
- 백업: 서버 시작 시 1회와 6시간마다 `plugins/MinecraftRPG/backups/`에 저장하고 최근 20개를 남긴다. 복원은 서버를 끈 뒤 `scripts/restore-db.sh <백업파일>`로 한다.

보상 정확히 한 번 보장 (2026-10-03 보강):
- 지급한 아이템에는 확정 전 잠금 표식이 붙는다. `CLAIMED` 커밋 전에는 옮기기·버리기·사용·액자 거치가 막히고, 사망해도 떨어지지 않는다. 그래서 "지급됐는데 인벤토리에 없음"으로 잘못 판단해 다시 주는 일이 없다.
- 복구할 때 아이템이 일부만 있어도 지급된 것으로 본다. 아이템은 한 번에 함께 들어가므로, 일부가 없다면 관리자 삭제 같은 외부 개입이다. 없는 아이템은 다시 주지 않고 경고 로그를 남긴다.
- EXP는 `CLAIMED` 트랜잭션으로만 영속된다. 완료가 커밋될 때까지 그 플레이어의 일반 저장을 미루고, 완료 쓰기가 실패하면 5초부터 30초까지 간격을 늘리며 재시도한다. 성공 알림과 잠금 해제는 커밋 뒤에만 한다.
- 프로필 버전은 커밋이 확인된 뒤에만 올라간다. 쓰기가 실패하면 다음 스냅샷이 DB의 실제 버전을 기대하도록 되돌리고, 변경분은 dirty로 남겨 다시 저장한다.
- 검증용 관리자 명령: `/rpgadmin dbfail <save|record|transition|complete> <횟수>`, `/rpgadmin testgrant <플레이어> <EXP> [장비...]`

바닐라 우회 차단:
- RPG 장비는 제작·모루·숫돌·대장장이 작업대 재료가 될 수 없다. 주민 거래·화로·양조대 등 작업 칸에도 넣을 수 없다.
- 관리자가 아닌 플레이어는 크리에이티브 복제를 할 수 없다.
- RPG 몹은 바닐라 변환(익사 좀비화 등)을 하지 않는다. 바닐라 드롭과 경험치도 남기지 않는다.
- 이 차단들은 E2E로 확인하지 않았다(봇으로 작업대 UI를 조작하지 않음).

슬라이스 1에서 남은 것:
- 사망 시 바닐라 규칙대로 RPG 장비도 떨어진다(잠긴 아이템 제외). 사망 페널티를 정하면 바꾼다.
- 몹 기여·소유권은 메모리에만 있어 서버를 재시작하면 초기화된다. 보상 원장은 영속되므로 중복 지급은 없다.

## 통과 조건

1. 고정한 Paper 빌드가 부팅되고, 플러그인이 오류 없이 켜지고 꺼진다: `EULA_ACCEPTED=true scripts/run-server.sh --boot-test` — **2026-10-03 통과**
2. 단위 테스트: 스탯 계산, 50% 상한, 피해 순서(ATK→증가→치명→DEF→방어막→HP→흡수), 쿨타임 하한 — **통과**
3. RPG HP가 1인 플레이어의 바닐라 체력이 0이 되지 않는다. 포만감·물약 회복은 차단하고, HP 0일 때만 사망한다. 사망 후 재접속해도 상태가 유지된다. — **E2E 통과**
4. 2인이 같은 몹을 처치해도 보상은 한 번만 생성된다. 공용 보스는 수령 자격을 얻은 플레이어마다 정확히 한 번씩 보상을 받고, 자격 없는 플레이어는 받지 못한다. — **E2E 통과**
5. 지급 도중 서버를 강제 종료하면, 재시작 후 보상함에서 한 번만 수령할 수 있다. — **E2E 통과**(플레이어 데이터 저장 전·후 두 지점)
6. 백업 파일로 복원하면 성장 데이터가 일치한다. — **E2E 통과**
7. 바닐라 갑옷·인챈트 효과가 RPG DEF와 이중으로 적용되지 않는다. — **E2E 통과**

보류: 직업 교체 검증(교체 전후 자원, 시전 중 교체 거부, 쿨타임·진행 효과 유지, 재접속 유지)은 직업을 구현하게 되면 그 슬라이스의 통과 조건으로 넣는다. 던전 동시 인스턴스 상한과 재시작 후 정리는 슬라이스 2에서 검증한다.

## 시험값 (나중에 바꿀 수 있음)

- 입력 방식: 좌클릭은 기본 공격. 우클릭·F키는 직업 구현 때 다시 정한다.
- 레벨 1~10 EXP 곡선은 임시 공식을 쓴다. 최대 레벨 60은 계산용 가정이다.
- 표시는 액션바·보스바·스코어보드만 쓴다. 리소스팩은 쓰지 않는다.
- 전투 이탈 5초, 방어막 부여 15%/30%/10%, 환경 피해 비례 변환은 design.md의 값을 그대로 쓴다.
- 공용 보스 수령 자격: 보스 최대 HP의 5% 이상 피해를 준 플레이어(시험값). 일반 몹은 첫 타격자가 소유한다.
- 첫 목표 플레이 루프: 전투 → 보상 → 장비로 성장 → 더 강한 몹/보스.
- 성능은 2~5인 기준으로 측정한다. 합격선은 목표 동시 접속 규모를 정할 때 확정한다.
