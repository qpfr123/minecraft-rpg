# 던전 맵

던전은 **정의(YAML)** 와 **템플릿 월드**로 이루어진다. 플레이어가 입장할 때 템플릿 월드 폴더를 복사해 인스턴스를 만든다.

- 정의: `plugins/MinecraftRPG/dungeons/<id>.yml`
  - 표시 이름, 최대 인원, 입구, 몹 스폰, 보스, 클리어 보상
  - 좌표는 템플릿 월드 기준
- 템플릿: 서버 폴더의 `rpg_tpl_<id>/`
  - 평소에는 언로드 상태로 둔다
  - `rpg_layout_version.txt`에 출처를 기록한다
    - `generated:<버전>`: 코드 생성기가 만든 템플릿
    - `edited`: 게임 안에서 편집한 템플릿
- 정의 파일을 고쳐 몹 수나 보상을 바꾸는 데에는 코드 수정이 필요 없다. 서버를 재시작하면 적용된다.

## 기본 던전: 지하 납골당(crypt) v2

바닥 높이는 y=63이고, 남쪽 입구에서 북쪽(+z)으로 진행한다.

| 구역 | 범위 | 내용 |
|---|---|---|
| 입구 홀 | x -5..5, z -5..5 | 입구 (0.5, 64, -3.5), 랜턴 |
| 구울 방 | x -10..10, z 20..36 | 기둥 4개, 구울 4 |
| 궁수 방 | x -12..12, z 48..66 | 양옆 2층 회랑(서는 높이 y=67)과 계단, 2층에 해골 궁수 3, 1층에 구울 2 |
| 보스 투기장 | x -14..14, z 77..103 | 기둥 4개, 단상(서는 높이 y=65), 납골당 파수꾼 |

- 각 구역은 폭 5의 회랑으로 이어진다.
- 벽과 바닥 재질, 장식은 고정 시드로 놓기 때문에 항상 같은 맵이 만들어진다.
- 생성기 버전(`DungeonRegistry.CRYPT_LAYOUT_VERSION`)이 바뀌면 다음 시작 때 템플릿을 다시 만든다.
  - 게임 안에서 편집한 템플릿(`edited`)은 다시 만들지 않는다.
  - crypt를 편집해 저장하면 생성기에서 분리된다(YAML의 `generator`가 지워진다).

## 게임 안 편집기

관리자 권한(`minecraftrpg.admin`)이 필요하다.

```text
/rpgadmin dungeonedit create <id> <이름>   새 던전(9x9 돌 발판)을 만들고 편집 월드로 이동
/rpgadmin dungeonedit edit <id>            기존 던전 맵 편집
/rpgadmin dungeonedit list                 편집 중인 던전
(편집 월드 안에서)
  setentrance           지금 위치·방향을 입구로
  addspawn <몹>         지금 위치에 일반 몹 스폰 추가 (ghoul, bone_archer, grave_knight)
  setboss <몹>          지금 위치를 보스 위치로 (crypt_warden)
  removespawn           3칸 안 가장 가까운 스폰 삭제
  spawns                현재 설정 보기
  name <이름> | maxplayers <1~4>
  save                  검증 후 저장
  cancel                편집 버림
```

- 편집 월드에 들어가면 크리에이티브 모드가 된다. 저장하거나 취소하면 원래 위치와 게임 모드로 돌아간다.
- 입구, 스폰, 보스 위치는 떠 있는 글자로 표시된다. 이 표시는 저장되지 않는 엔티티라 인스턴스에 복사되지 않는다.

### 편집이 안전한 이유

- **작업 사본에서 편집한다.** 편집은 템플릿을 복사한 작업 사본 `rpg_edit_<id>/`에서 한다.
  - 편집하는 동안에도 플레이어는 기존 템플릿으로 입장한다.
  - 진행 중인 인스턴스도 영향을 받지 않는다.
- **저장은 저널 방식이다.** YAML과 맵이 어긋나지 않도록 아래 순서로 저장한다.
  1. 검증한다. 입구, 보스, 등록된 몹, 인원 1~4, 스폰 최대 60개를 확인한다.
  2. 편집자를 원래 위치로 돌려보내고, 편집 월드를 저장한 뒤 언로드한다.
  3. 저널 `<id>.save-journal`을 쓴다. 여기에는 이전 템플릿을 옮겨 둘 폴더 이름이 들어간다.
  4. 새 정의를 `<id>.yml.new`로 쓴다.
  5. 템플릿을 `rpg_old_*`로 옮기고, 사본을 템플릿 자리로 옮긴다.
  6. `<id>.yml.new`를 `<id>.yml`로 원자적으로 교체한다. **여기가 확정 지점이다.**
  7. 이전 템플릿과 저널을 지우고 레지스트리를 갱신한다.
- **중간에 꺼져도 복구된다.** 서버를 시작할 때 정의를 읽기 전에 저널을 확인한다.
  - `.yml.new`가 남아 있으면 확정 전이다. 맵과 정의를 모두 이전 상태로 되돌린다.
  - `.yml.new`가 없으면 확정 후다. 남은 정리만 마저 한다.
  - 저장 중 입출력 오류가 나도 같은 방식으로 즉시 되돌린다.
- **준비 중인 인스턴스가 있으면 저장을 미룬다.** 같은 던전의 인스턴스를 준비하는 중이면(다른 스레드가 템플릿 폴더를 복사하는 중이면) 저장하지 않고 다시 시도하라고 알린다.
- **진행 중인 인스턴스는 입장 당시 정의를 따른다.** 입장할 때 정의를 인스턴스에 고정하기 때문에, 진행 중에 저장해도 보스 판정, 클리어 보상, 리스폰 입구가 바뀌지 않는다. 바뀐 정의는 새 인스턴스부터 적용된다.
- **편집자 상태를 복구한다.** 편집 월드로 들어가기 전에 원래 위치와 게임 모드를 DB(`editor_sessions`)에 먼저 기록한다.
  - 편집 중 로그아웃했다가 재접속했는데 편집이 아직 진행 중이면, 편집 월드로 복귀한다.
  - 편집이 끝났거나 서버가 꺼진 뒤 접속하면, 원래 위치와 게임 모드로 되돌리고 기록을 지운다.
  - 복귀 순서는 이동 → 모드 복원 → 플레이어 데이터 저장 → 기록 삭제다.
- **저장하지 않은 편집은 버린다.** 서버가 꺼질 때 저장하지 않은 편집은 버리고, 다음 시작 때 남은 `rpg_edit_*`, `rpg_old_*` 폴더를 정리한다.
- **미완성 던전은 입장할 수 없다.** 입장할 때 정의를 다시 검증하고, 통과하지 못하면 입장을 거절한다.

## 검증

`EULA_ACCEPTED=true scripts/e2e.sh editor` (e2e/editor.mjs)를 실행하면 다음을 확인한다.

- 생성과 저장
  - 새 던전을 만들고 블록을 지은 뒤 위치를 찍어 저장한다.
  - 입장했을 때 블록과 몹 배치가 맞고, 편집 표시가 없는지 본다.
- 편집 중 동작
  - 편집 중에는 기존 맵으로 입장된다.
  - 진행 중인 인스턴스는 저장의 영향을 받지 않는다.
  - 저장한 뒤 새로 입장하면 고친 맵이 나온다.
- 취소와 검증
  - 취소하면 블록과 이름 변경을 버린다.
  - 보스가 없는 던전은 저장이 거절된다.
- crypt 편집
  - crypt를 편집하면 생성기에서 분리되고, 재시작해도 덮어쓰지 않는다.
- 재시작
  - 편집 중 종료하면 사본을 정리한다.
  - 재시작한 뒤에도 저장한 던전이 유지된다.
  - 예전 형식의 템플릿 표시는 v2로 다시 생성된다.
- 정의 고정
  - 진행 중인 인스턴스가 있을 때 입구와 보스를 바꿔 저장해도, 기존 인스턴스는 이전 입구에서 리스폰하고 이전 보스를 잡으면 클리어 보상을 받는다.
  - 새 인스턴스는 바뀐 입구를 쓴다.
- 편집자 복구
  - 편집 중 재접속하면 편집 월드로 복귀한다.
  - 오프라인 상태에서 편집이 종료되거나 서버가 강제 종료된 뒤 접속하면, 원래 위치와 게임 모드로 돌아온다.
- 저장 중 강제 종료(`/rpgadmin dungeonedit crash <단계>`)
  - 이 명령은 `-Dminecraftrpg.testHooks=true`로 띄운 서버(scripts/e2e.sh)에서만 동작하고, 기본 실행에서는 거절된다(E2E로 확인).
  - after-stage, after-template-moved, after-swap에서 꺼지면 정의와 맵이 모두 이전 상태로 돌아간다.
  - after-commit에서 꺼지면 정의와 맵이 모두 새 상태다.
  - 어느 경우든 저널과 `.yml.new`는 남지 않는다.
